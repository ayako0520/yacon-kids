# クラウドセッション用：ヤーコンたんけん隊！（試作）

## 始める前の準備（あなたが行う）

1. GitHub で新しいリポジトリを作る：https://github.com/new
   - 名前の例：`yacon-kids`
   - 公開設定：**Private**
   - 「Add a README file」にチェック（空のリポジトリだとクラウドで選べない場合があるため）
2. 要件定義書（Markdown）を、リポジトリの `docs/requirements.md` として追加する（GitHub の画面の「Add file」→「Create new file」に貼り付けて保存）。
3. Claude のクラウドセッションを開き、GitHub と連携して、このリポジトリを選ぶ。
4. 下の「指示文」を貼り付けて開始する。

## 指示文（ここから下をそのまま貼り付ける）

---

このリポジトリで、日本ヤーコン協会の子ども向けページ「ヤーコンたんけん隊！」の**試作**を作ってください。
要件は `docs/requirements.md`（要件定義書 v1.0）にあります。最初に全文を読んでください。

### 今回の範囲

要件定義書の **B案（静的な HTML・CSS・JavaScript）** で、協会に見せて仕様を確認するための試作を作ります。

- 対象：小学3〜4年生（保護者・先生も一緒に見る）
- 構成：第2章の8セクション（intro、plant、origin、grow、eat、nutrients、quiz、adults）を、1ページの縦長構成で作る
- クイズ：第4章の動作仕様案どおり。初期は4問・各3択。問題データは JSON などで原稿と分け、3〜5問に変えても画面を作り直さずに済むようにする
- JavaScript が動かないときの代替表示（全問題と、折りたたみの正解・解説）も作る

### 必ず守ること

1. **原稿は仮のもの**とし、すべての本文・問題・解説に「【要監修】」の印を付ける。植物・原産地・栽培・成分について、根拠のない数値や断定を書かない（第3章）。
2. **成分の章は、健康効果を期待させる表現を使わない**（第6章の表の「初期公開時の扱い案」に従う）。「血糖値を下げる」「やせる」「豊富」などは使わない。
3. **絵本のイラストは使わない**（許諾が未確認のため、第5章）。図版は、色付きの四角に「図版の予定：〇〇」と書いた仮の枠にする。外部の画像やフォントも読み込まない。
4. 個人情報の入力、Cookie、ローカルストレージ、アクセス解析、外部への通信を入れない。
5. 第7章のモバイル・アクセシビリティ要件（N01〜N10）を設計目標にする：幅320・375・768・1280px で崩れない、本文18px以上、ボタンは44×44px以上、コントラスト、キーボード操作、`ruby` によるふりがな、正誤を色だけで伝えない、`prefers-reduced-motion` を尊重する。
6. 第8章の SEO の基本（`lang="ja"`、H1は1つ、見出しの順序、タイトル、説明文）を入れる。検証用なので `<meta name="robots" content="noindex">` を付ける。
7. 文章は、です・ます調。1文はおよそ40字以内。

### 作るもの

- `site/index.html`、`site/styles.css`、`site/quiz.js`、`site/quiz-data.json`（ファイル名は変えてもよい）
- `README.md`：試作の見方（ブラウザで開く方法）、ファイル構成、要件定義書との対応
- `docs/checklist.md`：第11章の受入基準（AC01〜AC14）について、試作で対応した点・未対応の点・協会の確認が必要な点を表にまとめる
- `docs/open-questions.md`：第13章の未確定事項（U01〜U11）のうち、試作を作って新たに分かった質問

### 作業の進め方

- 作業用のブランチを作り、プルリクエストにまとめてください。`main` には直接入れないでください。
- コードのコメントは日本語で書いてください。
- 終わったら、プルリクエストの説明に「できたこと」「確認してほしいこと」「未対応のこと」を書いてください。
