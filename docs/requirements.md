## 1. 文書の位置づけと確定範囲

本ページは、小学3〜4年生がヤーコンを知り、植物・原産地・栽培・食べ方・成分を学び、クイズで振り返るための日本語の学習ページとする。

本書の「確定」は今回の依頼で明示された要求を指す。協会による正式承認や、過去の詳細仕様の承認を意味しない。参照チャットから取得できた履歴では当該ページの詳細合意を確認できないため、実装上の補足は提案または要確認として扱う。

| 区分 | 意味 | 実装への扱い |
| --- | --- | --- |
| 確定 | 今回の依頼で明示された要求 | 必須範囲として扱う |
| 提案 | 実装可能な形に具体化した仕様案 | 協会の承認後に実装仕様とする |
| 要確認 | 情報不足または関係者の判断が必要な事項 | 決定者と期限を定め、依存作業の着手前に解消する |

### 1.1 確定する要求

- 日本ヤーコン協会の子ども向けページを対象とし、名称を「ヤーコンたんけん隊！」とする。
- 主な対象を小学3〜4年生とする。
- 植物、原産地、栽培、食べ方、成分、3〜5問のクイズを含める。
- 絵本イラストを使用する。**利用許諾は取得済み**（2026年11月4日に依頼者から連絡）。許諾の範囲は素材台帳で管理する。
- 阿見町のマスコットキャラクター「**あみっぺ**」を使用する方向とする。**クレジット表示を必須**とする。
- 栄養表現の法令配慮を扱う。
- モバイル対応、アクセシビリティ、SEOを実装要件に含める。
- WordPressへの追加案と静的サイト案を比較し、管理保守・セキュリティを定義する。
- 受入基準、未確定事項、工程を示す。
- 成果物は編集可能なMarkdown形式とする。価格は記載しない。

### 1.2 目的と範囲の提案

**提案：** 子どもが「どんな植物か」「どこから来たか」「どう育てて食べるか」を自分の言葉で説明できることを学習目標とする。保護者・教員が一緒に閲覧する場面も想定する。

初期公開は学習本文、図版、クイズ、協会サイトとの相互導線、保護者・先生向けの出典案内までとする。通販、会員登録、投稿、ランキング、個人別学習履歴、動画制作、多言語化、協会サイト全体の移行は初期範囲に含めない案とする。追加する場合は仕様を再合意する。

## 2. 情報設計と画面構成

**提案：** 1つのURLにまとめた縦長ページとし、冒頭の目次から各章へ移動できる構成にする。章ごとに短い説明と図版を配置し、最後にクイズを置く。URL案は `/kids/` とするが、既存URLとの重複やサーバー構成を確認して決定する。

| 順序 | セクションと識別子案 | 主な内容 | 区分 |
| --- | --- | --- | --- |
| 1 | 導入 `intro` | タイトル、学べること、目次、開始ボタン | 提案 |
| 2 | ヤーコンってなに `plant` | 全体像、葉・茎・花・地下部の図解 | 内容は確定、構成は提案 |
| 3 | どこからきたの `origin` | 原産地の説明と位置がわかる地図 | 内容は確定、構成は提案 |
| 4 | どうやってそだつの `grow` | 植え付けから収穫までの流れ | 内容は確定、構成は提案 |
| 5 | どうやってたべるの `eat` | 食べる部位、調理例、親子での注意点 | 内容は確定、構成は提案 |
| 6 | なにがふくまれるの `nutrients` | 成分の紹介と個体差などの補足 | 内容は確定、構成は提案 |
| 7 | たんけんクイズ `quiz` | 3〜5問、回答、解説、再挑戦 | 問数の範囲は確定、動作は提案 |
| 8 | おうちの方と先生へ `adults` | 監修、出典、更新日、権利表示、協会へのリンク | 提案 |

導線は「協会トップから本ページ」「本ページから協会トップ」「各章から目次」「クイズ解説から該当章」を設ける案とする。外部リンクはリンク先が分かる文言を付け、子どもを意図せず販売ページへ誘導しない。

## 3. コンテンツ要件

### 3.1 文章と表記

**提案：** 本文はです・ます調で統一し、1文は40字程度、長くても60字程度を目安とする。1段落は2〜3文、各学習章は200〜350字程度を初稿の目安とし、理解しやすさを優先して調整する。

- 小学3年生までの既習漢字を基準に、未習漢字、専門語、地名にふりがなを付ける。実装は原則としてHTMLの `ruby` を使う。
- 「原産地」「成分」などは、やさしい言い換えと一緒に説明する。
- 図にしか存在しない重要情報を作らず、同じ内容を本文でも説明する。
- 断定が難しい事項は「地域によってちがいます」など条件を添える。
- 原稿の事実確認・監修者を協会が指定する。児童による試読は保護者等の同意と学校等の手続きを確認したうえで実施する任意案とする。

### 3.2 各章で満たす内容

以下は掲載項目の**提案**であり、植物学・栽培・食品に関する最終原稿は協会の監修を要する。本書は未確認の数値や栽培条件を公開原稿として確定しない。

| 要件ID | 章 | 原稿に含める事項 | 公開前の確認事項 |
| --- | --- | --- | --- |
| C01 | 植物 | 植物としての分類、見た目、食用になる地下部、繁殖に使う部位との違い | 学名・分類・部位名と図の対応。食用部と種苗用部を混同しない |
| C02 | 原産地 | 南米アンデス地域を説明する案と、日本との位置関係が分かる地図 | 原産地域の範囲、日本への導入を載せる場合の年代と根拠 |
| C03 | 栽培 | 植え付け、生育、収穫、保管の順序と観察ポイント | 日本のどの地域を基準にするか。月・気温・栽培期間を全国一律にしない |
| C04 | 食べ方 | 食用部の紹介、生食・加熱の例、洗浄や調理時の注意 | レシピの実作確認、材料、分量、アレルゲン、包丁・火を使う際の大人の補助 |
| C05 | 成分 | 水分、糖類などの位置づけ。フラクトオリゴ糖等を扱うか検討 | 根拠資料、対象部位、品種・貯蔵・調理条件、数値の単位と測定条件 |

成分章は「何が含まれるかを学ぶ」構成とし、治療や健康効果を期待させる構成にしない。根と葉、食品と抽出物、一般的な成分研究と個別食品の効果を区別する。

### 3.3 出典と原稿管理

**提案：** 原稿ごとに、原稿ID、掲載文、根拠資料名、著者・機関、公開年、URLまたは書誌情報、参照箇所、確認日、監修者、承認日を原稿台帳に記録する。事実確認には公的研究機関・学術資料・協会保有資料を用い、一般サイトの転載のみを根拠にしない。

子ども向け本文では説明を短くし、詳細な出典は「おうちの方と先生へ」にまとめる。出典資料の文章・図版をそのまま使用する場合は、事実の参照とは別に利用条件を確認する。

## 4. クイズ機能

**確定：** 問数は3〜5問。**提案：** 初期公開は4問、各問3択、1問ずつ回答して解説を読む方式とする。原稿と問題データを分離し、3〜5問へ変更しても画面の作り直しが不要な実装とする。

### 4.1 問題案

| 問題ID | 学習内容 | 出題案 | 正解と解説の条件 |
| --- | --- | --- | --- |
| Q01 | 植物 | 食べる部分を図から選ぶ | C01の監修済み図と本文に一致させる |
| Q02 | 原産地 | もともとのふるさとを選ぶ | C02で確定した地域表現と一致させる |
| Q03 | 栽培 | 成長の順序として正しいものを選ぶ | C03の図解だけで答えられるようにする |
| Q04 | 食べ方 | 包丁を使うときの行動を選ぶ | 大人と一緒に行う説明を正解にする |

成分に関する問題を追加する場合も、健康効果の断定を正解にしない。問題案と正解は原稿監修後に確定する。

### 4.2 動作仕様案

1. 初期表示は未回答で、現在の問題番号と総問数を表示する。
2. 選択肢はラジオボタンとラベルで実装する。「こたえあわせ」は未選択時に理由を示し、回答を促す。
3. 回答確定後に正誤、正解、短い解説、該当章へのリンクを表示する。確定済み回答は再挑戦まで変更しない。
4. 解説を読んで「つぎへ」を押すと次問へ進む。正誤や進行は支援技術でも認識できるよう通知し、フォーカスを適切に移動する。
5. 最終回答後に正解数と復習案内を表示する。点数による否定的な評価や他者との順位比較は行わない。
6. 「もういちど」で全問を未回答に戻す。ページ再読み込みでも初期化し、サーバー・Cookie・ローカルストレージに成績を保存しない案とする。
7. JavaScriptが動かない場合は、全問題と折りたたみ式の正解・解説を読める代替表示を用意する。

問題データは `id`、問題文、選択肢IDと文言、正解ID、解説、復習先IDで構成する。時間制限、音声の自動再生、個人情報の入力は設けない案とする。

## 5. 絵本イラスト・あみっぺと素材の権利

**確定：** 絵本イラストの利用許諾は**取得済み**（2026年11月4日に依頼者から連絡）。阿見町のマスコットキャラクター「あみっぺ」を使用する方向とし、**クレジット表示を必須**とする。

**要確認：**

- 絵本：絵本名、版、著者・画家・出版社、許諾の相手方と確認方法・日付、許諾の範囲（下の記録項目）。
- あみっぺ：阿見町が指定するクレジット表示の文言と表示位置、使用申請の要否と手続き、使用できる画像・ポーズ、禁止事項（変形・色変更・他キャラクターとの組み合わせ等）、使用期間。

協会が絵本や原画を所有していることと、ウェブ掲載・加工の許諾を持つことは区別する。許諾を判断できる権利者または正当な代理人を確認する。[S05]

**提案：** 素材ごとに次を記録し、掲載前に書面または保存可能な電子記録で確認する。

- 利用するページ・図版・キャラクターと元データの識別情報。
- 掲載サイトとドメイン、利用目的、公開期間、利用地域、商用性の扱い。
- ウェブ掲載、複製、公衆送信に関する許諾範囲。
- トリミング、縮小、圧縮、背景除去、色変更、文字追加、アニメーション化の可否。著作者人格権に関する必要な同意も個別確認する。
- 著作者名・作品名・出版社名などのクレジット文と表示位置。あみっぺは阿見町が指定する文言を一字一句そのまま表示する。
- OGP画像、SNS告知、印刷教材、ダウンロード配布への利用可否。ウェブ掲載の許諾を自動的に流用しない。
- 制作担当者へのデータ提供、配信サービスへのアップロード、制作作業での外部サービス（ソース管理・AI を含む）の利用、保管方法、許諾終了時の対応。

許諾範囲外の素材は試作時の公開環境に置かない。許諾の範囲で使えない用途（例：OGP）には、協会が権利を持つ写真や新規制作図版を使う案を承認する。素材台帳には利用条件と証跡の保存先を記録する。

## 6. 栄養と健康に関する表現

**確定：** 栄養表現に法令上の配慮を行う。**提案：** 以下を公開前の編集・審査ルールにする。

教育ページという名称だけで法令の適用を判断せず、販売サイトとの関係、リンク、画像、見出し、クイズを含む表示全体から確認する。健康増進法・景品表示法上の問題となる健康表示、医薬品的な効能効果の標ぼうを避ける。[S01][S02]

| 表現の種類 | 初期公開時の扱い案 |
| --- | --- |
| 成分名の紹介 | 対象部位と根拠を確認し、監修済みの事実として記載する |
| 含有量の数値 | 出典、100g当たり等の基準量、単位、生・加熱等の条件を併記する。別条件の数値を混在させない |
| 「豊富」「低カロリー」等の強調 | 根拠と基準、掲載形態による食品表示基準等との関係を確認するまで採用しない |
| 「血糖値を下げる」「病気を予防する」等 | 初期原稿では採用しない。研究の紹介でも食品の確実な効果に置き換えない |
| 「必ずやせる」「だれでも安心」「たくさん食べよう」等 | 保証・過剰摂取・安全性の断定につながるため採用しない |
| 特保・機能性表示食品に見える表現 | 個別制度の対象・条件を確認せず一般のヤーコンに用いない |

食品表示基準の容器包装への適用と、ウェブ上の広告・教育情報への適用は分けて確認する。「含む」等の表現も文脈と対象食品により確認が必要であり、すべてのウェブ説明に一律の表示義務があるとは扱わない。[S03]

**提案する審査手順：** 制作担当者が文言と根拠を一覧化し、協会の監修担当者が科学的妥当性を確認する。販売促進との関係や法的判断が残る表現は、必要に応じて専門家・所管窓口に確認する。協会の公開承認者が最終承認する。免責文を添えるだけで問題表現を残さない。

## 7. モバイルとアクセシビリティ

**確定：** モバイルとアクセシビリティに対応する。以下の数値・検証範囲は**提案**とし、採用後は受入条件とする。

| 要件ID | 要件案 | 検証条件 |
| --- | --- | --- |
| N01 | レスポンシブ表示 | 幅320・375・768・1280 CSS pxで本文・クイズに横スクロール、重なり、欠けがない |
| N02 | 本文の読みやすさ | 本文18 CSS px以上を基本とし、行間1.7程度。端末設定の文字拡大を妨げない |
| N03 | 拡大とリフロー | 200%文字拡大、1280px幅で400%ズーム相当の表示でも情報・機能を失わない |
| N04 | 操作領域 | 主要ボタン・選択肢は44×44 CSS px以上を設計目標とし、隣接操作との間隔を確保する |
| N05 | コントラスト | 通常文字4.5:1以上、大きな文字3:1以上、意味を持つUI・図の境界3:1以上を確認する |
| N06 | キーボード操作 | 全リンク・クイズをTab・Shift+Tab・矢印・Enter・Space等の適切なキーで操作でき、閉じ込めがない |
| N07 | フォーカスと構造 | フォーカスを視認でき、固定要素に隠れない。本文スキップ、論理的な見出し、適切なボタン名を設ける |
| N08 | 支援技術 | 画像の代替テキスト、装飾画像の空alt、問題グループ名、選択肢ラベル、結果通知を実装する |
| N09 | 色と動き | 正誤を色だけで伝えず文言・記号を併用する。自動点滅・自動再生を避け、動きを減らす設定を尊重する |
| N10 | 読み上げ | WindowsのNVDA＋Chrome、iPhoneのVoiceOver＋Safariで本文・目次・クイズ一式を手動確認する |

WCAG 2.2 AAを設計・検証の目標とする。[S04] 上記の抜粋チェックだけでAA全体への適合を宣言しない。正式な適合表明が必要な場合は、対象ページ・基準・試験方法・結果の公表範囲を別途合意する。

**提案する対象環境：** 検収開始時点のChrome・Edge・Firefox・Safariの最新安定版、iOS Safari・Android Chrome。試験したOS、端末、ブラウザ版を記録する。学校の制限付き端末や旧版対応の必要性は要確認とする。

## 8. SEOと表示性能

**確定：** SEOに配慮する。**提案：** 検索順位の保証は行わず、検索エンジンと利用者が内容を理解できる基本構造を実装する。

- タイトル案は「ヤーコンたんけん隊！ 小学生のためのヤーコンずかん｜日本ヤーコン協会」。説明文は監修済みの内容から作成する。
- `lang="ja"`、内容を表すH1を1つ、順序の整った見出し、本文のHTMLテキスト、適切な代替テキストを用意する。
- 正規URLを1つ決めてcanonicalを設定する。WordPress版と静的版の重複公開を避ける。
- 協会サイトから通常のリンクで到達できるようにし、サイトマップへ反映する。更新日・運営主体・監修情報を表示する。
- 検証環境は認証で保護し、検索対象外にする。公開時は本番の認証解除、noindexの解除、robots設定、リンク切れを確認する。
- OGPには使用許諾済み画像のみを使う。構造化データは実際の内容に一致する場合に限り採用し、検索結果の特別表示を前提にしない。
- 画像は適切な大きさと形式で圧縮し、幅・高さを指定する。ファーストビュー以外は遅延読み込みを検討する。主要画像まで遅延させない。
- 外部フォント・広告・第三者スクリプトを最小限にする。解析ツールは目的と管理者を決めてから採用する。

**性能の暫定目標：** 公開相当環境のモバイル条件でLCP 2.5秒以下、CLS 0.1以下を目標とする。INP 200ms以下は公開後に実測データが得られる場合の改善目標とし、実測がない初回検収ではクイズの操作遅延を手動確認する。測定条件と測定回数を固定し、既存テーマや配信環境による制約は検収前に合意する。これらの数値は提案値であり、現状性能を保証するものではない。

## 9. 実装方式の比較と選定

**確定：** 次の2案を比較する。**要確認：** 既存サイトがWordPressかどうか、管理権限、サーバー、テーマ、PHP等の構成、契約上の変更可能範囲。実地確認前に既存構成を断定しない。

| 比較項目 | A案 WordPressに追加 | B案 静的HTML CSS JavaScript |

**選定提案：** 協会職員が管理画面から継続更新するならA案を優先する。更新が少なく、制作担当者による更新が許容されるならB案を優先する。最終判断は既存環境、更新担当者、更新頻度、公開権限を確認して行う。

本ページだけを静的化しても、残るWordPress全体の保守はなくならない。同一サーバーで認証情報や書込権限を共有する場合は、その影響も確認する。協会サイト全体の移行は本書の初期範囲に含めない。

### 9.1 実装上の提案

A案では、既存テーマ本体への直接編集を避け、子テーマまたは目的を限定したプラグイン等にページ固有処理を分離する。クイズのためだけに大規模な外部サービスを導入しない。管理画面で編集できる箇所と、担当者の作業が必要な箇所を明示する。

B案では、HTML・CSS・JavaScriptと素材をまとめ、閲覧時に外部APIを必須としない。更新元と公開物の対応を記録し、同じ手順で再公開・差し戻しできるようにする。ビルドツールを使う場合は依存関係と実行手順も引き継ぐ。

### 10.1 実装と公開の対策案

- HTTPSを使用し、HTTPからの転送と混在コンテンツの解消を確認する。
